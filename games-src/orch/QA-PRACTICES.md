# QA practices: how others ship few bugs, and what we adopt (W660, 24 Nov)

Owner problem: bugs (clipped text, overlaps, stuck turns, wrong rules, dead buttons, broken tutorials) are found by playing. We need machines to find them first.
Source note: facts come from search-result summaries of the cited pages (pages not opened in full); the SETTA figure and the target-size rule are quoted as the summaries gave them.

Our existing tools: `scripts/*` (qa-bot.js phase fuzz, phone-check.js, scenarios.spec.js with `?scn=` states, rulestest.js + per-game rules-test.js, ui-audit.spec.js, contact-sheet.js, turbo.js, gauntlet.js). NEW: `scripts/monkey.js`.

## Practices

| # | Practice | Who uses it | Cost | Our bug types it catches | Mapping in this repo |
|---|---|---|---|---|---|
| 1 | **Monkey / random-tap playouts with invariants** (seeded, replayable): click random actionable things for N steps, assert no exception, not frozen, not blank. | gremlins.js https://www.npmjs.com/package/gremlins.js (random clicks in Playwright via addInitScript); Android Monkey https://developer.android.com/studio/test/monkey (`-s seed` replays the same events; a SETTA 2023 study https://tingsu.github.io/files/SETTA_2023.pdf found only 36.6% of crash replays reproduced because runtime context differs, so keep the game deterministic per seed) | Low (built: monkey.js, ~15-45 s a game) | JS errors, stuck turns, dead ends, ghost overlays, blank screens | `scripts/monkey.js <slug> --seed N`, replay file, runs on turbo.js |
| 2 | **Model-based / property tests**: random command sequences against the engine, invariants (cards conserved, no negative resources, terminates), shrinking to the smallest failing sequence. | fast-check https://fast-check.dev/docs/advanced/model-based-testing/ | Medium: needs engines to expose state/moves as pure functions | Wrong rules, scoring errors, illegal states | extend `rules-test.js` files; `rulestest.js` runner; per game |
| 3 | **Deterministic seeded engine + mock RNG, scenario tests from a built state** | boardgame.io https://github.com/boardgameio/boardgame.io/blob/cdb73580351266e25154dbfed10ab745b44d70af/docs/documentation/testing.md (moves are plain functions, `MockRandom`, scenario tests) | Already have | Wrong rules, regressions | `?scn=` scenarios + scenarios.spec.js; add one scenario per fixed bug |
| 4 | **Uniform legalActions()/apply()/isTerminal() interface, random agent over every game** | OpenSpiel https://ar5iv.labs.arxiv.org/html/1908.09453 ; random legal-action agent with seeded env https://arxiv.org/html/2508.03368v2 | Medium: per-game adapter (30 games) | Crashes, non-terminating games, no legal move | optional `window.__legal()` hook; monkey.js could call it instead of DOM guessing |
| 5 | **Automated agents (scripted, then learning) playing builds** | EA SEED https://www.ea.com/seed/news/automated-game-testing-deep-reinforcement-learning and https://www.ea.com/seed/news/seed-ml-research-aaa-game-testing (RL agents added to scripted bots: coverage up, exploits and bugs found; they caution RL is not always the practical choice) | High for RL; low for scripted bots (we have them as game AIs) | Exploits, balance, crashes | AI-vs-AI self-play batches through each game's computer opponent; flag win-rate far from fair |
| 6 | **Visual regression baselines** | Playwright https://playwright.dev/docs/test-snapshots (`toHaveScreenshot`, `maxDiffPixels`, `mask`; fix environment, freeze animations); Storybook + Chromatic https://storybook.js.org/docs/writing-tests/visual-testing (pixel diff, human accepts change) | Medium: baselines per screen, flake control (turbo already freezes animation) | Clipped text, overlaps, layout drift after shared changes | `contact-sheet.js` shots become baselines; `baselines.sh` exists |
| 7 | **Accessibility / layout linting** | axe-core via Playwright https://playwright.dev/docs/accessibility-testing (scan per screen state); WCAG 2.2 target size https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum (>= 24x24 CSS px, we use 44 on phones) | Low | Tiny tap targets, contrast, missing labels | qa-bot `statics()` and ui-audit.spec.js already do font/overflow/tap/overlap; add axe scan as a second opinion |
| 8 | **Data validation vs component lists** | ajv-cli https://github.com/jessedc/ajv-cli/ (JSON Schema, exit 1, valid/invalid fixtures) | Low | Missing/duplicate cards, wrong counts, bad ids | one schema + count check per game's card data; run in guard.py |
| 9 | **Definition of Done enforced by machine** | Scrum.org https://www.scrum.org/resources/what-definition-done ; GitHub required status checks https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches | Low | Self-reported "done" that is not | already: ui-audit.spec.js is the gate; add monkey.js clean run to the checklist |
| 10 | **Run tests on every build at scale** | a large online-game studio's build-verification team, ~100,000 test cases a day https://technology.riotgames.com/node/33 | Principle only | Regressions from shared changes | build-all.py `--quick` already; add monkey as a check |
| 11 | **In-game bug report with seed + action log** | Sentry feedback https://docs.sentry.io/platforms/javascript/user-feedback ; Unity User Reporting https://docs.unity.com/cloud-diagnostics/en/manual/UserReporting/ConfiguringUserReporting (attach state to the report) | Medium: one shared button in the shell | Everything the owner finds by playing, with a repro | shared shell "Report bug" button -> JSON {slug, build, seed, taps} that monkey.js `--replay` can read |
| 12 | **Playtest triage from structured logs, not comment volume** | Valve playtest guidance https://partner.steamgames.com/doc/features/playtest (developer owns feedback collection; tell testers what to report) | Low | Prioritisation | triage by seed + screen id into QUEUE.md |

## Ranked adoption plan
1. **Monkey playouts (done, this task)**: cheapest, fully automatic, found a real crash on the first 6 games. Next: add to `build-all.py --quick` as a non-blocking check, run 3 seeds per game nightly.
2. **Bug-report button with seed + taps (11)**: turns every owner finding into a replayable file; monkey.js already writes and reads that format.
3. **Schema/data validation (8)**: an hour per game, kills wrong-count/missing-card bugs.
4. **Property tests on engines (2) + one `?scn=` per fixed bug (3)**: catches wrong rules; start with the 5 most-played games.
5. **Visual baselines (6) from contact-sheet shots**: after shared-shell changes only.
6. **axe scan (7)** as a second opinion beside ui-audit.
7. **Self-play batches (5)** for balance, later.
Teach monkey.js two things first: tap the tutorial's spotlighted target (it now leaves a tutorial by its Skip button), and use `__legal()` where a game offers it.
