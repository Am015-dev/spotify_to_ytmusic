# Tidewake: online play (free peer-to-peer, no server)

Files: `net.js` (page side), `src/netstrip.js` (new: what a seat may see), small hooks in `ui1.js`..`ui5.js` (ui.js is their join), `body.html`, `head.html`, `build.py`; shared `net/trystero.min.js`, `netroom.js` inlined by build.py (never edited). `src/engine.js`, `data.js`, `ai.js` untouched. Tests: `tools/net-strip-test.js`, `SP/net/p2p-tw.js` (copy of the test).

## Model (copied from Short Fuse)
* The host's page holds the real `G`, runs the engine, the computer seats and the animations. Seats go to players in join order (host = seat 0); seats beyond the humans are computers (level and colours from the start screen). Teams need 4, 6 or 8 seats (the plan rounds the crew up to the next even number, at least 4); solo variants are refused online with a message.
* **Hidden information: whitelist.** `netStrip(G, seat)` builds a NEW object from a list of public fields (nothing is copied by default; a field the engine adds later is absent until listed). Other captains' hands = same length of `-1`, draw pile = `-1`s (count only), leviathan deck = sorted contents only (public: every leviathan not on the board), elimination pool and the drawn-cannon card only for their owner, other seats' question options/ctx/title of a private question empty, agenda empty, rng and seed absent. Each peer gets its own copy through `room.sendTo` (compressed, 3200-char chunks, throttled to 300 ms plus a 3 s heartbeat). The host screen draws only its own hand (`viewSeat()` = my seat online, no pass screen, no x-ray).
* Clients send `{m: move}` only. Host: sender owns a human seat, plain small JSON object with a string `a`, `legal(m, seat)` accepts it (so it is the current `sideToAct()` and one of `genMoves`), then it goes through the same `act()` as a click. Moves that arrive while the host plays an animation wait in a queue of 6 and are re-checked when applied. Rejections come back as a message line.
* **Interrupts** (Deck Cannon / Rift Gate on another captain's turn) are the ordinary `G.q` owned by the endangered seat: only that page gets the options. The existing 25 s timer (forced on online, also if the local setting is off) runs on the host: if the owner does not decide, the host answers with the computer's best advice (`aiMove(.., 'hard')`), exactly as in local play. Clients only draw the bar.
* Leave: the seat becomes a computer seat (a pending question included, `schedule()` is re-run); the same browser uid rejoining gets it back. Host leaving ends the game ("The host left. The game is over.", Leave button); no migration because the others never hold the hidden state.
* UI: start screen has a "Play with friends" card (name, Host, invite code, Join; `#join-CODE` prefills it). Lobby popup: code, invite link + Copy (select fallback), captains with their sail colours, the crew size, Set sail / Change setup / Close the room (client: Leave); X, Esc and a tap outside close it. Dock strip: room, "you are <colour>", status, Lobby, Leave. Start screen in a room: online captains show as "Online: name" rows, no hot-seat/watch choice, no guided game or saved-game continue. Clients get a "waiting for the host" page, a game-over card without Play again/New game, and a Leave button in the menu. Late joiners watch. Online games are never saved locally.
* Clients replay the host's moves: the host keeps the recorded events of its last 8 moves (public facts only: dice, tiles, sails, leviathan steps, sinks) and sends them with each snapshot; the client copies only whitelisted fields (`cleanEv`), plays the ones it has not seen against its own kit, then reconciles to the snapshot (`netPlay`). If another snapshot arrives meanwhile it is applied afterwards. Same cards (wake roll, Sunk!, expansion labels) as the host. Animations off = the old instant update.
* **Idle-turn timer** (host setting in the lobby: Off / 30 / 60 / 90 s, default off): when the captain to act (host included) does nothing, the host plays the computer's move for that one turn; everyone sees the countdown in the dock strip (the lobby shows the setting). Interrupts keep their own 25 s timer. Host "Play again" / new setup starts a fresh game on every page.

## Known gaps
* Rejoin was flaky only when 3-5 test groups (each 3 Chromium contexts, software GPU) ran at the same time: 2 of about 5 parallel runs never reconnected (transport level, the rejoined page never saw the host); 4 of 4 sequential runs passed. Real networks, TURN, phones and 5+ humans are untested (4 humans tested).
* Engine facts, not changed: `knowledge()` still exposes another seat's question option count and a private question's title ("You drew a Deck Cannon") and the log line "already holds two Deck Cannons" is public; the strip hides the first two, the third is a rules-text choice for the engine owner.
* A captain who is idle on their own turn is waited for (only interrupts time out). No host migration. Pause is not shared. Sounds on clients come from the replayed events.
* The first version of `ui4.js` was briefly truncated by a bad edit and restored byte for byte from `ui.js` (28,115 bytes, as before); all later edits are the hooks listed above.
